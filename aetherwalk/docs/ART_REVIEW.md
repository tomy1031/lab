# AETHERWALK 景観監修レビュー（art review）

監修：FABLE の代行（Opus）　対象：統合後の v1（`?desktop&nosound&fresh&seed=1`、SwiftShader で撮影。fps ではなく見た目で判断）
読む人：OPUS-A（手・持ちもの・ホルスター・PC 表示・アイテムの形と効果）、OPUS-B（敵・予告・宝箱まわりのロジック・HUD・手首メニュー・PC オーバーレイ）

この文書の約束
- 優先度：**P1 = 直さないと出せない**／P2 = 直すべき／P3 = できれば。各項目に「担当・ファイル・何が悪いか（撮影ファイル）・目標・受け入れ」を書いた。迷ったら DESIGN.md §7 に合わせる。
- 撮影ファイルは `docs/shots/` にある。`review_*.jpg` は指摘の証拠（いまのみなさんの実装のまま）。`vista_*.jpg` は `node tests/shots.cjs vista` の出力（手袋が映っているのは A-P1-1 のため）。
- 色は §7.1 の決まりを守る：良いもの＝金 `#ffd76a`・水色 `#7fe9ff`・白 `#fffbe8`、予告＝`#ff3b5c`（これ専用）、凪＝灰 `#6b6770`／芯 `#c23bff`、火 `#ffb347 → #ff6a2b`。
- マテリアルは `ctx.art.material()`（Lambert 相当＋共通の霧）か `ctx.art.basic()`。光るものは「明るい basic ＋ `ctx.art.glow()`」。`MeshStandardMaterial`・`PointLight`・影は使わない。`fog: false` の素の `MeshBasicMaterial` は霧に溶けず浮くので、世界に置くものには使わない。
- 予算（§7.6）は変えない：OPUS-A ≤ 16 ドローコール／8k 三角形、OPUS-B ≤ 30／16k。下の目標はすべてこの中に収まる。

### B-P1-4　予告（`#ff3b5c`）が草の上で茶色に濁り、近いと画面が桃色に染まる
- 担当：OPUS-B　ファイル：`js/game/enemies.js`（`buildTelegraphGeos`・予告のマテリアル・`teleTick`）
- 何が悪いか：`review_enemies.jpg` の中の列（`lurker` の突進の帯は茶色、`rimeguard` の扇は橙の幕、`husk` の足もとの帯は肌色）。不透明度 0.14〜0.72 の一枚板を緑の上に重ねるので色相がずれる。深度テストなしの大きな扇の中に立つと画面ごと桃色になる。
- 目標：予告は「縁（読ませる）＋中（範囲）＋動き（向き）」の 3 つで作る。マテリアルは今の `MeshBasicMaterial`（`depthTest: false`・`depthWrite: false`）のままで良い（`art.basic` はキャッシュを共有するので、使うなら `.clone()` してから `depthTest = false`）。色は `#ff3b5c` だけ（これ専用）。
  - **縁**：形の外周に幅 0.06 m の帯、不透明度 0.95 一定。予告の最後の 25% は `#ff8fa3` まで明るく点滅（8 Hz）。
  - **中**：不透明度 0.16 → 0.38（時間で上がる）。プレイヤーが形の中にいるときは中の不透明度を 0.12 で止める（縁だけで読ませる）。
  - **動き**：帯（`line`）と扇（`fan`）の中に、攻撃の向きへ 2.5 m/s で流れる山形の縞（幅 0.25 m、不透明度 +0.15）。地割れ・突進の「来る向き」が一目でわかる。
  - **頭の高さ（`high`）**：水平の板は目の高さだと真横から見えて消える。頭の高さ y に**縦 0.10 m の光の帯**（腕の届く弧に沿う、プレイヤーを向く）を、不透明度 0.9 で引き、両端に `art.glow({ color: 0xff3b5c, size: 0.25 })`。
- 受け入れ：昼の草原で 4 m と 12 m から各攻撃を撮り、縁の色が赤紫（茶・橙・肌色に見えない）。`rimeguard` の扇の中に立っても、画面全体の色が桃色にならない（予告の外の草が緑のまま）。
- **直した（2026-11-11）**：縁・中・縞・頭の高さの縦帯（`js/game/telegraph.js`）。`high` の中は地面に寝かせた（胸の高さの板が 40 m 先まで地面を覆い、画面が桃色になっていた原因）。
