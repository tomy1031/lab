# レポート画面：実装向け改善メモ

1. **朝の判断順に並べる。** 1536×1024の画面では、上部64pxを共通ヘッダー、中央を幅約1396pxのダッシュボード、最下部を共通ドックにする。「見出し → 人間待ち → KPI → 分担・拠点別実績・ランキング → 拠点状況・完了報告」の順に配置。CSS Gridと16〜20pxの間隔で整列し、ドックと本文が重ならない余白を確保する。
2. **オフィスを感じるガラス面。** 元の3Dオフィスを背景にし、背景レイヤーのみを軽くぼかす。カードは `background:rgba(245,252,255,.86)`、`backdrop-filter:blur(20px)`、白い1px枠、24px角丸、青みのある柔らかな影で統一する。文字の後ろは十分に白くし、装飾の発光は輪郭に限定する。カードの透明感はCSSで実装し、モックアップ画像のアルファ値とは分けて扱う。
3. **人間待ちを最優先にする。** 見出し直下にオレンジの帯で「人間待ち 1件」を表示し、「確認する」から該当タスクへ移動する。人間のアバターと待機ラベルを併記し、色だけで状態を伝えない。0件なら帯をコンパクトな解消状態に切り替える。経過時間はデータ取得時のみ表示する。
4. **KPIを同じ構造に統一する。** 5枚を等幅で並べ、ラベル15〜16px、数値40〜44px、補足13〜14pxにする。Noto Sans JPなどの日本語書体を使い、数値には `font-variant-numeric:tabular-nums` を指定。値はプロジェクト0・進行中1、タスク4（AI4／人間0）、採用AI3・協働人間6、平均対応時間「—」、成果物4を維持。「—」はゼロ扱いせず計測待ちと説明する。
5. **グラフには比較できる基準を設ける。** 分担ドーナツはAI100%を中央に表示し、凡例にAI4件／人間0件を併記。拠点別バーは共通スケールで大阪3・東京0・プノンペン1を表す。タスク・成果物の推移は実際の履歴取得後に描画し、ホバー・フォーカスで日時と値を表示する。モックアップのスパークラインは形状例であり、履歴値や前期比を捏造しない。
6. **アバターと国旗で識別を速くする。** ランキングは白いロボットのAIアバター、順位、名前、完了件数を同じ列に揃える。アイ2件・ダラ1件・ルコ1件を表示。拠点には日本／カンボジア国旗と拠点名を併記。オンラインと稼働中は別項目として扱い、大阪は稼働中0・オンライン1、東京とプノンペンはともに0を保つ。
7. **色の役割を固定する。** 主操作・選択状態はシアンからブルーのグラデーション、完了は緑、人間待ちはオレンジ。本文は濃紺、補助文字は青みのあるグレーとし、背景とのコントラストを確保する。小さな光沢アイコンは参考のドックと同じ丸み・立体感に統一し、本文グラフを飾りすぎない。
8. **完了報告は空状態と展開状態を設計する。** 現在は完了プロジェクト0のため、ネクマックスのアバターと「まだ完了報告はありません」を表示し、進行中1件への導線を置く。報告が届いたら見出し行を `button` にし、`aria-expanded` と `aria-controls` 付きのアコーディオンで成果物・担当・完了日時を展開する。空状態で無効な「すべて見る」操作を出さない。
9. **共通ナビゲーションと操作感を守る。** 上部の拠点フィルターと下部6項目を維持し、レポートだけを青い面・白いアイコン・光の縁で選択表示する。ボタンは44px以上の操作領域と明確なフォーカスリングを持たせる。狭い画面ではKPIを折り返し、分析カードを縦積みにする。期間フィルターを変えたら全集計の対象を揃え、拠点の現在状態とは区別する。
